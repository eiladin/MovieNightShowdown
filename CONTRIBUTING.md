# Contributing

Thanks for taking an interest. This is a small, self-hosted project, so the
process is deliberately light.

## Getting set up

You need Go (the version in `go.mod`) and Node 24. Docker is optional but is
the easiest way to run the whole thing.

```sh
# Backend
go build ./... && go run .

# Frontend, with hot reload against a running backend
cd web && npm install && npm run dev

# Everything, the way it ships
docker compose up --build
```

The Go server serves the built frontend from `web/dist` and embeds it into the
binary, so a production-style run needs `cd web && npm run build` first. The
Dockerfile does this for you.

You do not need a Jellyfin server to work on this. At least one movie source
must be configured — Jellyfin, a TMDB read token for streaming services, or
both — and with neither the app serves an in-app setup guide explaining what is
missing. See `docs/INSTALL.md` for the environment variables.

## Before you open a pull request

Both suites must pass. CI runs exactly these:

```sh
gofmt -l .            # must print nothing
go build ./...
go vet ./...
go test ./...
golangci-lint run ./...

cd web
npm run lint
npx tsc -b
npm test
npm run build
```

`golangci-lint` is configured in `.golangci.yml` and is tuned for bugs rather
than style. If it flags something you believe is correct, say so in the pull
request rather than adding a blanket suppression.

## Conventions

- **Commits** follow [Conventional Commits](https://www.conventionalcommits.org)
  (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`, `perf:`, `ci:`).
  The release notes are generated from commit ranges, so the prefix matters.
- **Pull requests are squash-merged**, so the PR title becomes the commit
  message on `main`. Give it the same Conventional Commits shape.
- **`main` is protected.** Work on a branch, open a pull request, and let the
  three required checks (`go`, `web`, `build`) pass.

## Architecture notes

`CLAUDE.md` in the repository root is the fullest description of how the pieces
fit together and which invariants matter. It is written for coding agents but
is accurate and readable for humans; read it before a non-trivial change.

The two rules most easily broken by well-meaning patches:

- **Sources are enumerated server-side.** `GET /api/library/filters` reports
  what this deployment can query, and the frontend renders exactly that. Do not
  add a client-side list of streaming services.
- **Capabilities are declared, not inferred.** A source states what it supports
  by implementing an optional interface in `server/source.go`, and the answer
  travels to the client on `SourceDescriptor`. Never branch on a source id to
  decide what a source can do, on either side.

## Screenshots

`docs/screenshots/01-landing.png` through `05-result.png` are generated by a
deterministic pipeline that runs the real app against a mock Jellyfin server
with fictional placeholder movies, so it needs no real server and no personal
data:

```sh
make screenshots
```

`docs/screenshots/hero.png` is hand-curated and is not touched by that pipeline.

## Reporting bugs

Open an issue with what you expected, what happened, and the relevant server
log lines. If you think you have found a security problem, do not open an
issue — see [SECURITY.md](SECURITY.md).
